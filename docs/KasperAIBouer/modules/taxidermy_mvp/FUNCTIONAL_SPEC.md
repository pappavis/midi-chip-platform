# TAXIDERMY_MVP — FUNCTIONAL SPEC (STARTER)

## Candidate actors
- Admin / office user
- Taxidermy operations user
- Client
- Optional hunter / outfitter intermediary

## Candidate core flows
1. New client / order intake
2. Trophy / job item creation
3. Item traceability and coding
4. Photo / evidence attachment
5. Quote and deposit status capture
6. Production status tracking
7. Client viewing / approval interaction
8. Final payment status capture
9. Ready-for-shipping or collection status

## MVP intention
The first MVP should likely include:
- intake
- item linkage
- attachments
- statuses
- limited portal visibility
- approval capture
- payment-status fields
not necessarily:
- real payment integration
- real courier integration
- real-time WhatsApp automation

## Out-of-scope for now
- generalized CRM core
- full multi-module platform design
- advanced reporting
- accounting sync
- AI image recognition

## Functional warnings
- state transitions must be strict
- one client must not see another client’s work
- item identity and linkage are non-negotiable


## v0.2 reminder
Future CRM potential may be referenced, but may not dilute current MVP boundaries.
