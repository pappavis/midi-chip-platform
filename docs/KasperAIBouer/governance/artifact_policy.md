# ARTIFACT POLICY

## Doel
Artefakte is die geheue, verifikasiepad en handofflaag van die projek. Niks belangriks mag net “in die chat” leef nie.

## Minimum artefakte per module
- Project Charter
- Source Synthesis
- Assumptions Register
- Business Case
- Functional Spec
- Risk Register
- Backlog
- QA Checklist
- Release Notes

## Stylvereistes
- duidelike titels
- kort inleiding
- leesbaar vir 'n mens
- aannames eksplisiet
- bekende gaps apart gemerk
- waar moontlik: bullets / tabelformaat vir duidelikheid
- geen vals afrondingstaal

## Versionering
Gebruik eenvoudige weergaweformaat soos:
- `v0.1`
- `v0.2`
- `v1.0`

## Wat moet veranderings log
Elke betekenisvolle artefakverandering moet een of meer van hierdie note hê:
- Added
- Changed
- Fixed
- Removed
- Notes
- Risks

## Simulasie vs werklik
Waar iets nog nie reg geïntegreer of getoets is nie, moet dit duidelik gemerk word as:
- simulated
- assumed
- not yet validated
- placeholder

## Mensleesbaarheid
Docs moet geskryf wees vir:
- Michiel
- Kasper
- toekomstige developer
- reviewer
Nie net vir nóg 'n model nie.


## v0.2 refinement

- decision logs
- open questions registers
