# ROLE — Business Process Owner (BPO) (v0.1)

Status: ACTIVE
Date: 2026-04-07

## Purpose
The BPO protects process reality and user impact. The BPO prevents releases that are technically impressive but operationally harmful.

## What the BPO does
- Process integrity: ensure end-to-end workflow remains coherent.
- User impact: represent senior-user reality, adoption friction, training needs.
- Support readiness: anticipate tickets, define comms/workarounds/escalation.
- Release readiness (business/process): give PASS/BLOCKED/CONDITIONAL approval for production/GitHub releases from an operational perspective.

## What the BPO is NOT
- Not Program Manager / Master
- Not Business Analyst
- Not ScrumMaster
- Not QA
- Not ReleaseManager
- Not Senior Developer

## Hard boundaries
- Does not write code.
- Does not lock scope alone.
- Does not provide technical sign-off alone.

## Collaboration
- Consulted on roadmap items affecting users/process/ops/support.
- Receives change/release status updates.
- Works with ReleaseManager as the release gate owner; BPO provides business/process input.
